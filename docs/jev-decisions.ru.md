# Jev как ограниченный decision-provider для Stagehand

Эта интеграция добавляет отдельный метод `stagehand.decisionAct()`. Обычный `stagehand.act()` и исходный runtime Stagehand не заменяются. Jev выбирает один из предложенных кандидатов; текст действия, вводимые значения и проверку результата задаёт приложение. Это не универсальная замена генеративной модели и не автономный агент для произвольных задач.

Базовый upstream commit: `9afa0952453e219f7164a0ea16cf293d3dcaddde`.

## Как работает действие

1. Stagehand получает accessibility snapshot страницы.
2. Локальный код фильтрует элементы по допустимым ролям и ранжирует их по словам из инструкции и окружающих областей страницы. Выбирается ограниченный набор, по умолчанию до 24 элементов.
3. Провайдер получает только `{ id, description }`, инструкцию и необязательный `state`. XPath остаётся в локальном коде. Добавляется явный вариант `none`.
4. Jev возвращает choice, confidence, вероятности, модель, токены и время запроса. Адаптер проверяет структуру ответа и допустимость выбора.
5. Перед исполнением повторно проверяются snapshot, идентичность кандидата, единственность и видимость локатора.
6. Исполняется не более одного заранее заданного `click`, `fill` или `selectOption`.
7. Обязательный callback `verify` проверяет смысловой результат. Успешная отправка клика сама по себе не считается успехом задачи.

Нет автоматического перехода к `act()`, другой модели или угадыванию координат. Нет автоматических повторов действия. `none`, низкая уверенность, изменившийся DOM, ошибочный ответ провайдера и тайм-аут возвращаются как неуспех.

`confidence` является оценкой сервиса, а не гарантией и не измеренной вероятностью успеха в вашем приложении. Ограничение списка кандидатов может удалить правильный элемент. Проверяйте `candidateCounts` и подбирайте предел на репрезентативных задачах.

## Установка и сборка из checkout

Нужны версии Node и pnpm из корневого `package.json`, установленный Chrome/Chromium и возможность запускать его локально.

```bash
pnpm install --frozen-lockfile
pnpm --filter @browserbasehq/stagehand-extension build
NODE_OPTIONS=--max-old-space-size=4096 pnpm --filter @browserbasehq/stagehand build
```

Для запуска исходников можно явно указать установленный браузер и собранное расширение:

```bash
export CHROME_PATH=/usr/bin/chromium
export STAGEHAND_EXTENSION_DIRECTORY_PATH="$PWD/packages/extension/dist"
```

Пути адаптируйте к своей ОС. Не отключайте защиту браузера ради обхода ограничений среды. Ошибка запуска Chrome до появления debugging port является проблемой окружения, а не результатом измерения качества модели.

## Пример API

```ts
import { createJevDecisionProvider, localBrowser, Stagehand } from "@browserbasehq/stagehand";

const apiKey = process.env.JEV_API_KEY;
if (!apiKey?.trim()) throw new Error("JEV_API_KEY is required");

const browser = await localBrowser.launch({ headless: true });
const stagehand = await Stagehand.create({ browser });

try {
  const page = await stagehand.browser.context.newPage();
  await page.goto("http://127.0.0.1:3000/"); // Ваш локальный стенд.
  const provider = createJevDecisionProvider({
    apiKey,
    model: "jev-1.14.0",
    timeoutMs: 15_000,
  });
  const result = await stagehand.decisionAct("Fill the Destination field with Paris", {
    page,
    provider,
    action: { method: "fill", value: "Paris" },
    minConfidence: 0.8,
    maxCandidates: 24,
    timeout: 20_000,
    verify: async (currentPage) =>
      (await currentPage.locator("#destination").inputValue()) === "Paris",
  });
  console.log({ success: result.success, reason: result.reason });
} finally {
  await stagehand.close();
  await browser.close();
}
```

Для выбора в нативном `<select>` передайте `action: { method: "selectOption", values: ["economy"] }`. Для клика: `action: { method: "click" }`.

Безопасная проверка результата должна только читать страницу. После тайм-аута уже отправленный браузерный RPC или ваш callback могут ещё завершаться. Если `actionAttempted === true`, страница могла измениться даже при `success === false`: сначала проверьте фактическое состояние, не повторяйте действие автоматически.

Адаптер по умолчанию отправляет запрос на `https://api.typesafe.ai/v1/systemone`. Поддерживаются явные `model`, `baseURL`, `timeoutMs` и внедряемый `fetch` для контрактных тестов. Кастомный endpoint должен поддерживать именно System One schema, а не произвольный OpenAI-compatible API. Любой кастомный `DecisionProvider` обязан соблюдать тот же контракт. HTTP разрешён только для явных loopback-адресов; перенаправления запроса запрещены. В real benchmark кастомный транспорт и `baseURL` не используются.

## Контрактный smoke-тест: MOCK, не измерение модели

```bash
pnpm exec vitest run packages/sdk-ts/tests/browser-runtime/decisionActSmoke.test.ts
```

Этот тест поднимает HTML-стенд на `127.0.0.1` и настоящий локальный браузер. Детерминированный **MOCK** выбирает элемент только по `candidate.description`, не по DOM ID, локатору или позиции в списке. Он заполняет направление и даты, выбирает класс, нажимает поиск и проверяет точный текст результатов и число отправок формы. Дополнительно проверяются ложный postcondition и неизвестный candidate ID.

Токены mock равны нулю и модель явно называется `MOCK-description-contract-only`. Эти значения и время smoke-теста **нельзя** представлять как скорость, стоимость или качество Jev. Модель и платные API в smoke-тесте не вызываются.

В том же файле есть независимая проверка gate, не требующая браузера:

```bash
pnpm exec vitest run packages/sdk-ts/tests/browser-runtime/decisionActSmoke.test.ts \
  -t "benchmark approval gate"
```

## Настоящий сравнительный benchmark

Файл: `packages/sdk-ts/examples/decision-benchmark.ts`.

Оба варианта запускаются из одного checkout и используют один собранный браузерный runtime:

- **baseline:** исходный `stagehand.act()` с настоящим OpenAI Responses API через штатный `ClientLLM` callback. Инструкция и structured-output schema приходят из оригинального Stagehand. Ответ не подменяется mock.
- **jev:** новый `stagehand.decisionAct()` с настоящим Jev API. Метод и значения действия заранее известны приложению.

Перед платными запросами harness сравнивает исходный `act()` и исходники runtime расширения с закреплённым upstream SHA, а не с подвижным HEAD. При изменённом baseline или недоступной Git-истории запуск блокируется. В JSON записываются upstream SHA, текущий SHA, SHA-256 ключевых исходников, путь реально загружаемого расширения и хеши его manifest/service worker. Оба варианта используют этот же путь. Флаг `originalActSourceVerified` означает проверку исходников, а `loadedExtension.sourceEquivalenceVerified: false` прямо указывает на отсутствие аттестации сборки. Собирайте расширение из этого checkout перед запуском: проверка исходников сама по себе не удостоверяет происхождение ранее собранного бинарного артефакта.

### Обязательное разрешение расходов

Без **всех четырёх** непустых настроек ниже harness не запускает браузер и не делает API-запросов:

- `BENCHMARK_APPROVED=1` означает явное разрешение реальных платных вызовов для запуска.
- `OPENAI_API_KEY` для baseline.
- `JEV_API_KEY` для Jev.
- `BASELINE_MODEL` с конкретным OpenAI model ID. Модель baseline намеренно не выбирается молча.

Задайте секреты через безопасное окружение, не записывайте их в репозиторий, команды в документах или JSON-отчёты. Этот пример не загружает `.env` автоматически. Если ключа или разрешения нет, он сохраняет отчёт со `status: "blocked"`, списком отсутствующих настроек, `providerCalls: 0`, пустыми результатами и кодом выхода 2.

Проверка блокировки без ключей и расходов:

```bash
node --import tsx packages/sdk-ts/examples/decision-benchmark.ts \
  --out stagehand-artifacts/decision-benchmark-blocked.json
```

После отдельного разрешения расходов и настройки **обоих** ключей:

```bash
# BASELINE_MODEL задаётся вами; JEV_MODEL необязателен.
BENCHMARK_APPROVED=1 node --import tsx packages/sdk-ts/examples/decision-benchmark.ts \
  --scenario fixture --runs 3 \
  --out stagehand-artifacts/decision-benchmark.json
```

`--runs` принимает 1–20, по умолчанию 1. Каждый arm получает новый браузер без сохранённого профиля. Порядок baseline/jev меняется через один повтор. Скрытого warm-up, повторных запросов в Jev и fallback нет; автоматические retries OpenAI SDK отключены. Оригинальный `act()` может сделать несколько логических запросов, которые учитываются отдельно.

### Локальный сценарий по умолчанию

Оба варианта получают одинаковую HTML-страницу и пять одинаковых инструкций: направление Paris, даты 2027-06-15 и 2027-06-22, класс Economy, поиск. Для каждого шага используется одна и та же семантическая проверка. Финальная проверка требует точного содержимого результатов и ровно одной отправки формы. При неуспехе arm останавливается, без попытки угадать следующий шаг; второй arm запускается независимо.

Это намеренно простой детерминированный UI. Он проверяет интеграцию и позволяет сравнить расходы на данный сценарий, но не доказывает качество на произвольных сайтах.

### Google Flights: только открытие departure-airport picker

```bash
BENCHMARK_APPROVED=1 node --import tsx packages/sdk-ts/examples/decision-benchmark.ts \
  --scenario google-flights --runs 1 \
  --out stagehand-artifacts/google-flights-picker.json
```

Это **не полноценный поиск или бронирование перелёта**. Единственная операция: открыть поле `Where from?` на англоязычной странице Google Flights и проверить появление видимого диалога с полем аэропорта. Успех клика без диалога не засчитывается.

Перед действием проверяются домен, единственность ожидаемого поля и отсутствие уже открытого диалога, consent, CAPTCHA или обязательного входа. Baseline ограничен локатором этого поля; дополнительно ответ модели допускается только для его точного ID, `click` без аргументов и `twoStep: false`. Неподходящий ответ отклоняется, не переписывается; второй inference запрещён. Jev получает только этот кандидат и `none`. Нет заполнения личных данных, входа, обработки CAPTCHA, отправки поиска, покупки или перехода к продавцу. При неожиданной структуре страницы выполнение останавливается, а не угадывает другие контролы. Изменения сайта, региона или языка могут сделать проверку недоступной. Такой диагностический сценарий с одним кандидатом нельзя выдавать за измерение сложного выбора элементов.

### Что записывается в JSON

- Успех всего arm и каждого шага, reason и число завершённых шагов.
- Wall time всего запуска, arm и шагов. Arm включает запуск браузера и очистку; `actionWallTimeMs` включает действия и смысловые проверки, но не сохранение диагностики.
- Число попыток вызова провайдера, их фактические модели, время и usage.
- Входные, выходные и известные cached input tokens. При неизвестном usage сохраняется `null`, а не выдуманный ноль.
- Для нового метода: время snapshot, decision, revalidation, action и verification.
- При ошибке шага: локальные screenshot и snapshot JSON в каталоге `<report>.evidence`, либо явные ошибки сохранения диагностики. Основной отчёт содержит пути, а не DOM и секреты.
- Итоговые success rate, число запросов, токены, число проверенных шагов и среднее время отдельно по всем arm и только по успешным. Если успехов нет, `meanSuccessfulActionWallTimeMs` равен `null`. Сравнивайте время вместе с success rate и числом выполненных шагов: ранний провал не является ускорением.

Незавершённые callbacks отслеживаются. После ошибки baseline-запрос отменяется, а уже начатые callbacks завершаются до фиксации метрик. Это время включается в wall time; ещё исполняющийся вызов не записывается как нулевой.

Стоимость `costUsd` остаётся `null`, пока явно не указаны точные применимые ставки в USD за миллион токенов:

- `BASELINE_INPUT_USD_PER_MILLION`, `BASELINE_OUTPUT_USD_PER_MILLION`.
- `BASELINE_CACHED_INPUT_USD_PER_MILLION`, если появились cached tokens.
- `JEV_INPUT_USD_PER_MILLION`, `JEV_OUTPUT_USD_PER_MILLION`.

Не переносите рекламные цены между моделями или тарифами. Если тариф не выражается этими ставками, оставьте стоимость неизвестной. Ошибочный вызов с неизвестным биллингом также даёт `null`. Это оценка по введённым ставкам, не счёт провайдера. В отчёт не заложены предполагаемые цены или заявления об ускорении.

## Приватность и ограничения

- Jev получает названия доступных элементов, контекст областей страницы, инструкцию и явный `state`. В них может оказаться приватная информация. XPath не отправляется, но это не делает описания анонимными.
- Baseline получает данные страницы, выбранные оригинальным Stagehand для inference. Обе внешние передачи должны быть разрешены владельцем данных.
- Не добавляйте в `state` пароли, токены, cookie или сведения, не нужные для выбора. Секреты API не должны находиться в промпте.
- Для демонстрации используйте локальный стенд с синтетическими данными и новый профиль браузера. Google Flights режим также не подключает ваш обычный профиль.
- Диагностические screenshot и snapshot могут содержать видимые данные сайта. Хранятся локально с ограниченными правами в gitignored `stagehand-artifacts/`. Не коммитьте и не публикуйте их без проверки. Пользовательский `--out` может указывать вне этого каталога: ответственность за приватность пути остаётся у оператора.
- Граница безопасности здесь ограничивает выбор и повтор действия, но не заменяет разрешения на consequential actions, защиту от недоверенного содержимого страницы и ваши бизнес-правила. Не используйте пример для оплаты или других необратимых действий без отдельного контроля.

## Что действительно проверено в текущей среде

На этапе разработки gate успешно записал `blocked`-отчёт с нулём вызовов: разрешение расходов и ключи не предоставлены. Контрактный тест gate прошёл. Browser smoke не дошёл до действий: Chromium завершился с `SIGABRT` до готовности debugging port; тот же инфраструктурный барьер наблюдается у исходного browser smoke. Это **блокировка проверки в среде**, не пройденный browser smoke и не доказанный дефект decisionAct.

Реальный baseline/Jev benchmark и live Google Flights здесь **не запускались**. Числа latency, качества и экономии до настоящего разрешённого запуска отсутствуют.

Проверки разработки 2026-11-03:

- Non-browser SDK: 737 тестов в 30 файлах прошли, включая 117 новых provider/runner unit-тестов. Это не browser E2E и не оценка модели.
- Extension regression suite без e2e и extension-build test: 683 passed, 9 todo, 49 файлов.
- Независимый approval-gate test: 1 passed; 3 browser-case не выполнялись в этом запуске.
- SDK и extension собирались; SDK typecheck и publint проходили.
- Полный `pnpm check` не завершён: Mintlify validation остановилась на запрете `uv_interface_addresses` в среде. Общая проверка форматирования прошла. Этот запуск не объявляется полным зелёным CI.
